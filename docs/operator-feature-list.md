# 산란 특장점과 제공 기능

산란(saanraan)은 콘텐츠를 발행하고, 회원이 참여하고, 이용 권한과 혜택을 관리하는 **회원 중심 모듈형 PHP 웹 솔루션 베이스**다. 운영자가 발행하는 자료와 회원이 쓰는 게시글을 같은 계정·메뉴·알림·자산 체계 안에서 연결할 수 있다.

처음부터 모든 기능을 사용할 필요는 없다. 필요한 모듈과 의존 모듈을 설치하고, 쿠폰, 유료 이용, 작성자 보상, 외부 알림은 해당 모듈과 정책을 설정해 사용한다. 개발자는 PHP 파일에서 요청 흐름을 따라가며 사이트에 맞게 수정할 수 있다.

이 문서는 도입을 검토하는 운영자와 제작자를 위한 기능 소개다. 2026-10-06 기준 저장소의 30개 모듈·플러그인 선언, 요청 경로, 관리 화면, 연동 계약과 관련 구현을 다시 확인해 작성했다. 기능 구현을 설명하는 문서이며 **운영 신뢰성을 보증하는 검증 기록은 아니다**. 실제 운영 준비 상태는 [모듈 상태 등급](module-status.md)과 [검증 상태](verification-status.md)를 기준으로 판단한다.

## 기능을 조합하는 예시

- **회원 자료실·콘텐츠 서비스**: 공개 글과 회원 전용 자료를 함께 발행하고, 연재·검수·유료 열람·다운로드를 운영하려는 사이트.
- **주제별 커뮤니티**: 게시판마다 참여 조건을 달리하고, 댓글·멘션·리액션·스크랩·쪽지·활동 보상을 연결하려는 사이트.
- **콘텐츠와 커뮤니티를 함께 운영하는 사이트**: 공식 안내에서 토론으로, 회원 게시글에서 관련 자료로 자연스럽게 이동하게 만들고 싶은 사이트.
- **직접 수정하며 운영하는 소규모 서비스**: PHP와 MySQL 기반 호스팅에서 시작하고, 모듈별 기능과 데이터 흐름을 확인하면서 확장하려는 제작자·운영자.

## 산란의 핵심 특장점

### 1. 회원의 활동과 서비스 운영이 같은 기준으로 연결된다

콘텐츠를 읽는 사람, 게시판에 글을 쓰는 사람, 쿠폰을 사용하는 사람을 별도의 회원으로 관리하지 않는다. 같은 계정의 그룹, 활동, 자산, 알림과 개인정보 처리 흐름을 각 기능이 함께 사용한다.

예를 들어 회원 그룹을 유료 자료의 가격 정책에 연결하거나, 커뮤니티 활동 조건을 그룹 평가에 활용할 수 있다. 회원이 작성자로 참여하면 제출·검수·보상을 콘텐츠 운영 안에서 처리한다. 단순히 로그인 화면을 공유하는 데서 그치지 않고, 권한과 혜택을 같은 회원 기준으로 운영하는 것이 핵심이다.

### 2. 발행형 콘텐츠와 참여형 커뮤니티를 함께 구성한다

운영자가 관리하는 콘텐츠에는 예약 발행, 그룹, 시리즈, 작성자 제출·검수, 대표 이미지와 자료 다운로드가 있다. 커뮤니티에는 게시판 그룹, 게시판별 권한과 카테고리, 회원 글·댓글, 신고와 운영 조치가 있다.

두 영역은 각자의 운영 방식을 유지하면서 메뉴, 본문 링크·요약 임베드, 리액션과 알림으로 연결된다. 콘텐츠를 전부 게시판으로 만들거나, 회원의 대화를 발행용 페이지에 억지로 맞출 필요가 없다.

### 3. 혜택 제공부터 유료 이용의 사후 처리까지 다룬다

포인트·적립금·예치금, 쿠폰·이용권을 콘텐츠와 커뮤니티의 실제 이용에 연결할 수 있다. 회원 그룹별 정책, 이용권 우선 적용, 자산 차감, 최초 1회 접근권, 파일 다운로드 과금과 작성자 보상을 조합한다.

이용 이후에도 차감 내역, 쿠폰 사용, 접근권, 환불·회수와 실패 기록을 확인할 수 있다. 금액을 표시하는 기능과 운영자가 근거를 찾아 처리하는 기능을 함께 제공한다. 외부 카드 결제나 계좌 송금이 자동으로 실행되는 PG·은행 연동 서비스와는 범위가 다르다.

### 4. 디자인의 일관성을 유지하면서 화면 구성은 달리할 수 있다

공통·콘텐츠·커뮤니티의 공개 UI 킷을 제공하고, 관리자 UI는 별도로 관리한다. 버튼·폼·표·모달 같은 기본 요소는 재사용하면서 콘텐츠는 이미지 중심 갤러리, 커뮤니티는 게시판별 최신글, 읽기 화면은 본문과 댓글 중심으로 구성할 수 있다.

레이아웃, 테마, 스킨은 역할이 다르다. 지원하는 다른 모듈의 레이아웃을 선택해 헤더·푸터·메뉴를 공유하더라도, 본문의 기능과 표현은 해당 모듈이 맡는다. 사이트 전체의 사용법을 통일하면서 모든 화면을 같은 카드 목록으로 만들지 않을 수 있다.

### 5. 처리할 업무와 실패한 작업을 운영 화면에서 추적한다

관리자 대시보드는 서비스 현황, 처리 대기 업무, 자산·쿠폰 현황과 최근 활동을 모아 보여준다. 검수·신고·환불·출금처럼 판단이 필요한 업무는 해당 관리 화면으로 이어진다.

발송 실패, 보상 지급 지연, 저장소 정리 실패, 자산 잔액 불일치도 점검 대상으로 남긴다. 운영자는 확인 메모, 재시도, 취소, 정정처럼 각 기능이 제공하는 후속 절차를 사용할 수 있다. 작업이 성공했을 때뿐 아니라 끝나지 않았을 때 확인할 경로를 두는 것이 특징이다.

### 6. 개인정보 처리와 모듈 확장에 명시적인 연결 지점을 둔다

가입·제출 동의 당시의 문서 내용을 보존하고, 회원 사본 내려받기, 운영자 대응 기록, 탈퇴·익명화와 보존기간 정리를 연결한다. 새 모듈도 정해진 내보내기·정리 연동 방식을 구현하면 이 흐름에 참여할 수 있다.

코어는 실행 기반을 맡고, 회원 인증을 포함한 각 기능은 모듈이 자기 데이터와 정책을 소유한다. 절차형 PHP, 명시적 요청 경로와 파일 연결을 사용해 진입점·요청 경로·처리 파일에서 기능의 흐름을 확인할 수 있다.

## 실제로 구성할 수 있는 운영 흐름

아래 예시는 구현된 기능의 조합이다. 관련 모듈의 설치·설정과 대상별 권한·정책 설정이 필요하며, 한 번에 완성해 주는 사이트 템플릿을 뜻하지 않는다.

| 운영 예시 | 구성 방식 |
| --- | --- |
| 회원 전용 연재 자료실 | 콘텐츠 그룹으로 자료를 묶고 시리즈로 회차를 연결한다. 회원 그룹에 따라 이용 조건을 달리하고, 열람과 첨부 다운로드의 과금을 따로 정한다. |
| 외부 필자가 참여하는 매체 | 작성자 신청을 받고 제출본을 검수한다. 승인된 글을 공개하고 보상을 지급하며, 작성자의 수정안도 제출·승인 흐름으로 다룬다. |
| 참여에 따른 혜택이 있는 커뮤니티 | 게시판별 읽기·쓰기·댓글 조건을 정하고, 활동 점수·그룹 규칙과 게시판별 자산 정책을 연결한다. 신고와 숨김 조치는 운영자가 별도로 관리한다. |
| 쿠폰을 활용한 자료 제공 | 무료 발급 캠페인을 공개하거나 내부 자산으로 이용권을 발급한다. 사용처와 유효기간을 정하고, 회원은 쿠폰함에서 보유 내역을 확인한다. |
| 콘텐츠와 토론을 잇는 서비스 | 안내문 본문에 관련 게시글을 검색해 넣고, 토론 글에는 공식 콘텐츠를 연결한다. 공개 가능한 대상은 요약 임베드로 보여준다. |
| 알림과 사후 응대가 중요한 회원 서비스 | 사건별 알림 문구와 채널을 설정하고 발송 상태를 추적한다. 개인정보 사본은 회원이 직접 내려받고, 검토가 필요한 요청은 운영자가 대응 기록을 남긴다. |

## 분야별 기능

### 회원·인증·관계

| 기능 | 제공 범위 |
| --- | --- |
| 가입과 계정 관리 | 이메일·로그인 ID 기반 가입과 로그인, 이메일 인증, 비밀번호 변경·재설정, 계정 상태 관리, 탈퇴·익명화. |
| 계정 보안 | 이메일 코드·인증 앱(TOTP)·백업 코드를 이용한 2차 인증, 민감 화면 재인증, 세션과 인증 로그 관리. |
| 외부 로그인 | Google, Kakao, Naver, GitHub, Apple ID 제공자 플러그인과 OAuth/OIDC 계정 연결·해제. 사업자 앱 등록과 키 설정이 필요하다. |
| 본인확인 | KCP·KG이니시스 제공자 연동 구조, 가입 입력 보조, 계정 목적별 연결, 본인확인·성인 확인 결과를 사용하는 기능별 정책. 실제 사업자 인증 검증은 별도다. |
| 가입·프로필 항목 | 기본·추가 항목의 사용 여부와 순서, 닉네임, 프로필 이미지, 표시 크기 설정. 가입·회원 수정 화면과 개인정보 처리에 연결한다. |
| 회원 그룹 | 그룹 생성, 수동 배정·해제, 모듈이 제공하는 조건을 이용한 규칙과 평가. 접근 조건·가격·보상 정책에서 그룹을 활용한다. |
| 회원 간 관계 | 팔로우, 작성자 메뉴, 작성자 게시글 탐색, 쪽지 수발신·삭제·신고 연계, 쪽지 사용 여부와 보내기 조건 설정. |
| 회원 운영 | 회원 검색·상태 변경, 선택 컬럼 CSV 내보내기, 마케팅 수신 동의와 수신거부 반영. 민감 작업에는 재확인 절차를 둔다. |

### 콘텐츠 발행·자료 관리

| 기능 | 제공 범위 |
| --- | --- |
| 발행 상태 | 작성 중·예약·공개·숨김 상태, 관리자 미리보기, 공개 주소, 제목·요약·본문과 SEO 정보. 예약 시각이 지난 콘텐츠를 관련 조회 경로에서 공개로 전환하는 처리가 있으며, 지정 시각의 즉시 실행을 보장하는 설명과 구분한다. |
| 그룹과 시리즈 | 그룹별 공개 목록과 메뉴 연결, 시리즈 회차와 이전·다음 이동. 분류와 연재 순서를 따로 관리한다. |
| 작성자 참여 | 작성자 신청·승인·차단, 제출본 임시저장과 검수, 승인 콘텐츠의 수정안 제출, 작성자 보상과 지급 결과 확인. |
| 이미지와 파일 | 대표 이미지 URL·업로드, 공유용 이미지, 다운로드 파일, 썸네일 캐시와 이미지 없는 항목의 대체 표시. |
| 검색 | 공개 제목·요약과 열람이 허용된 본문 검색. 초안·숨김 및 접근이 제한된 본문은 공개 검색 대상과 구분한다. |
| 댓글과 반응 | 댓글·대댓글, 멘션 알림, 페이지별 대화 탐색, 공통 리액션. 기본 읽기 화면은 본문과 댓글을 별도 카드로 구성한다. |
| 완료 행동과 보상 | 콘텐츠의 완료 버튼에 자산 지급·차감 정책을 연결하고 중복 완료 여부와 처리 결과를 확인한다. |
| 복사와 정리 | 초안 복사, 그룹 적용 범위 선택, 삭제 후 파일·임베드·관련 데이터 정리 및 실패 확인. |
| 공개 표현 | 그룹별 갤러리, 대표 이미지와 설명, 데스크톱 사이드바, 콘텐츠별 레이아웃 선택. 레이아웃 없이 본문을 출력하는 선택지도 제공한다. |

| 게시판 구조 | 게시판 그룹, 게시판별 설정·카테고리·운영 스탭, 그룹과 게시판별 최신글을 모은 홈. |
| 참여 조건 | 읽기·쓰기·댓글 권한, 회원 그룹·최소 레벨 조건, 기능별 본인확인과 동의 설정. |
| 게시글 작성 | 작성·수정·공지·비밀글, 설정에 따른 작성·수정 중 자동 임시저장, 첨부와 본문 이미지, 추가 입력 항목, 에디터 선택. |

| 신고와 조치 | 신고 접수·검토·처리·기각, 대상별 운영 조치, 숨김 기간·사유·메모, 삭제 상태와 영구 삭제 구분. |
| 자료와 보상 | 유료 열람·첨부 다운로드, 게시자 보상, 결제·다운로드·지급·미회수 기록 확인. |

## 도입 전에 구분해야 할 범위

산란은 현재 1.0 릴리스 전 안정화 단계다. 구현된 기능이 많다는 사실과 운영 검증이 충분하다는 판단을 구분한다.

| 구분 | 현재 기준 |
| --- | --- |
| 구현과 검증 | `stable-candidate`와 `beta`는 검증 증거 수준이다. 특히 금액성 동시 처리·환불·복구·개인정보 처리와 실제 설치 환경 검증은 모듈별 상태를 확인해야 한다. |
| 외부 인증 | OAuth, KCP·KG이니시스, CAPTCHA는 연동 코드·설정 구조와 실제 사업자 계정 검증을 구분한다. 키를 입력하는 것만으로 모든 환경의 연동이 확인되는 것은 아니다. |
| 외부 결제 | 내부 자산 차감·쿠폰·이용권과 거래 기록은 구현되어 있다. 외부 PG 결제 선택 모듈과 기존 회원 마이그레이션은 계획 단계다. |
| 운영 자동화 | 대기열·예약·배치 작업에는 실행 주기와 실패 점검이 필요하다. 즉시 전달이나 모든 실패의 자동 복구를 약속하지 않는다. |
| 개인정보와 보안 | 동의·사본 제공·정리·보호 장치를 제공하지만 사이트별 운영 정책 검토와 보안 점검을 대신하지 않는다. |
| 성능과 운영 이력 | 이 문서에서 확인한 범위는 저장소의 기능 구현이다. 대규모 처리 성능, 장기 운영 안정성, 외부 테마·플러그인 생태계에 대한 평가는 포함하지 않는다. |

## 주요 설명의 구현 근거

아래는 기능 설명을 재확인할 수 있는 구현 위치다. 파일과 처리 경로의 존재를 실제 사업자 연동 성공이나 모든 상태의 운영 검증으로 해석하지 않는다. 모듈 설치·활성화 여부와 저장된 설정에 따라 실제 사이트에서 사용할 수 있는 범위가 달라진다.

| 확인한 내용 | 구현 근거와 범위 |
| --- | --- |
| 콘텐츠 상태와 예약 공개 | [콘텐츠 helper](../modules/content/helpers.php)의 상태 목록과 `sr_content_publish_due_scheduled` 및 호출 경로. |
| 콘텐츠 작성자 참여 | [작성자 신청](../modules/content/actions/account-content-author-application.php), [제출본 검수](../modules/content/actions/admin-content-submissions.php), [보상 내역](../modules/content/actions/admin-content-author-rewards.php). |
| 게시판 운영과 회원 활동 | [커뮤니티 요청 경로](../modules/community/paths.php), [그룹 평가 조건](../modules/community/member-group-rules.php). 게시판·댓글·신고·스크랩·시리즈 처리는 별도 action으로 제공한다. |
| 모듈 간 레이아웃 선택 | [콘텐츠 레이아웃](../modules/content/layout-options.php), [커뮤니티 레이아웃](../modules/community/layout-options.php), 각 모듈의 layout 설정과 helper. 지원 대상에 맞는 후보를 선택한다. |
| 사이트 메뉴 관리 | [사이트 메뉴 처리](../modules/site_menu/actions/admin-site-menus.php), [콘텐츠 메뉴 후보](../modules/content/menu-links.php), [커뮤니티 메뉴 후보](../modules/community/menu-links.php). |
| 자산 이용과 거래 기록 | [자산 간 환전](../modules/asset_exchange/actions/account-asset-exchange.php), [콘텐츠 결제 대상](../modules/content/payment-ledger-targets.php), [커뮤니티 결제 대상](../modules/community/payment-ledger-targets.php), [잔액 정합성 조회](../modules/asset_ledger/actions/admin-assets-reconciliation.php). 외부 PG 승인 기능의 제공 근거는 아니다. |
| 외부 로그인·본인확인 | [OAuth 제공자](../modules/member_oauth_providers/oauth-providers.php), [KCP 제공자](../modules/identity_kcp/identity-provider.php), [KG이니시스 제공자](../modules/identity_inicis/identity-provider.php). 제공자 코드와 실제 계약·계정 기반 검증을 구분한다. |
| 개인정보 사본과 대응 기록 | [회원 사본 내려받기](../modules/privacy/actions/account-privacy-export.php), [회원 안내 화면 처리](../modules/privacy/actions/account-privacy-requests.php), [운영자 대응 기록](../modules/privacy/actions/admin-privacy-requests.php). 회원 안내 경로는 요청 티켓을 접수하는 POST 기능을 제공하지 않는다. |

## 짧은 소개 문구

> 산란은 콘텐츠 발행과 커뮤니티 활동을 회원·권한·혜택·알림으로 연결하는 모듈형 PHP 웹 솔루션 베이스입니다. 필요한 기능부터 시작해 자료실, 참여형 커뮤니티, 쿠폰과 유료 이용을 조합하고, 운영 기록과 후속 처리까지 같은 사이트에서 관리할 수 있습니다. 현재 1.0 릴리스 전 안정화 단계이며 실제 도입 전에는 환경 요구사항과 모듈별 검증 상태를 확인해야 합니다.
